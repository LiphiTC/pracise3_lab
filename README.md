# Практика №3 · Вариант 3 · Наземная станция БПЛА

Самостоятельный проект `Practical_03_GroundStation`, C++17, Qt Widgets.
Выполнены варианты 3 заданий 1–3 и интеграционное задание из
«Практика 3 ПО ОНИ.pdf».

## Сборка и запуск

Откройте `CMakeLists.txt` в Qt Creator и выберите комплект Qt 6 или Qt 5.15.
Нужны модули Core, Widgets, Charts, 3DCore, 3DRender, 3DExtras, 3DInput,
Multimedia, Svg и Test (для проверок).

Из каталога `practise_3` (или корня отдельного репозитория проекта):

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j4
./build/Practical_03_GroundStation
ctest --test-dir build --output-on-failure
```

Модель можно собирать отдельно, без графических модулей:

```sh
cmake -S . -B build/model -DGROUNDSTATION_BUILD_GUI=OFF
cmake --build build/model
ctest --test-dir build/model --output-on-failure
```

## Работа станции

- При запуске оба аппарата на земле, статус `Stopped`, парк заполнен.
- «Старт · оба БПЛА» запускает общий таймер 100 мс. У каждого аппарата свой
  автопилот, комплект сенсоров, навигация, PID, высота, заряд и маршрут.
  Начальная цель — 200 м. «Пауза · оба» сохраняет состояние; «Старт» продолжает его.
- Список «Команды аппарату» выбирает получателя команд и отказов.
  «Взлёт» задаёт 200 м, «Посадка» — 0 м; обе команды запускают выбранный аппарат.
  «Стоп» замораживает только выбранный аппарат. Если остановлены оба, таймер
  выключается. Это учебный останов симуляции, не команда выключения реальных моторов.
- Целевая высота 0–500 м меняется без пересоздания модели. Ноль означает посадку.
  После команды взлёта/посадки поле автоматически показывает новую цель.
- Сигнал телеметрии каждого автопилота обновляет три отдельных слота: метки,
  таблицу парка и графики. На графиках показаны оба аппарата: Quad-1 — синий,
  Wing-2 — фиолетовый. Хранятся последние 600 измерений каждого аппарата.
- «Маршрут и крен»: два круговых маршрута на площадке 600 × 400 м, пунктир —
  план миссии, цветной след — пройденный путь. Маркеры и `QGraphicsPathItem`
  создаются один раз. `position_updated` перемещает маркер и задаёт
  `setRotation(roll)`, след дополняется через `QPainterPath::lineTo`.
- «3D-полёт» показывает те же аппараты с высотой, креном и следами. Камера:
  «Приблизить», «Отдалить», «К БПЛА», «Общий вид». Для уменьшения числа
  3D-объектов отрезки следа добавляются раз в секунду; маркеры движутся с частотой 10 Гц.
- «Отказ сенсора» переводит гироскоп выбранного аппарата в `Not ready`.
  На следующем его цикле модель сообщает причину: оба аппарата приостанавливаются,
  статус становится красным, в журнале появляется событие с временем модели,
  открывается предупреждение и звучит сигнал. Диалог показывается один раз до
  «Сброса». «Старт» и команды не обходят аварийную блокировку.
- «Сброс» восстанавливает сенсоры и навигацию обоих аппаратов, сбрасывает
  аварийную блокировку и PID, продолжает полёт с сохранённых координат и целей.
  Графики, маршруты и время сохраняются. Повторный сброс допустим.
- «Отказ GPS» переключает выбранный аппарат на INS на следующем цикле;
  жёлтый индикатор показывает резерв, таймер продолжает работать.
  «Восстановить GPS» возвращает GPS. Это дополнение нужно для обязательного
  интеграционного сценария из PDF. При недоступности всех систем возникает авария.
- Флажок звука управляет фоновым звуком полёта и сигналом отказа.

## Архитектура и стиль

`UAV` → `Quadcopter`, `FixedWingUAV`; `Sensor` → `Gyroscope`, `Accelerometer`,
`Barometer`; `NavigationSystem` → `GPSNavigation`, `InertialNavigation`,
`VisualNavigation`; `FlightController` → `PIDController`.
`NavigationManager` выбирает GPS → INS → Visual и испускает сигнал переключения.

`Autopilot : QObject` содержит `Q_OBJECT`, закрытое имя и режим, публичные команды,
слот `run_cycle()` и сигналы `telemetry_updated`, `position_updated`,
`fault_detected`, `mode_changed`. Два указательных `connect` связывают один
`QTimer::timeout` с двумя автопилотами. Модель зависит только от Qt Core,
не содержит виджетов и `qDebug`. В `MainWindow` нет PID, кинематики и выбора
навигации; команды идут через методы, результаты — через сигналы.
Окно владеет модельными модулями; QObject получают родителей.

Коэффициенты PID: Quad-1 — (0,5; 0,015; 0,05), Wing-2 — (0,35; 0,01; 0,04).
Учебная кинематика: выход PID — вертикальная скорость, ограниченная ±25 м/с;
движение по кругу с радиусом 100/150 м и скоростью 12/22 м/с; крен ±20°
имитируется моделью. Физика самолётного разбега и аэродинамика не моделируются.
Заряд снижается на 0,02% за секунду полёта и служит показателем телеметрии.

Как в `Practical_01_Task_1`, `Practical_02_Task_2` и `Kr2`, окно собрано
стандартными Qt Widgets в C++: группы, splitter, вкладки, таблица, журнал,
зелёные/жёлтые/красные состояния. Отдельный `.ui` не требуется.
Из `Kr2/Control_Work_02_Polymorphism` перенесены и адаптированы `Scene3D`,
`DroneVisual`, `FlightAudio`, `Point3D` и ресурсы `drone.jpg`, `fixedwing.svg`,
`drone_sound.mp3`, `critical.mp3`. Для графиков используется требуемый PDF
Qt Charts с цветами и сеткой прежнего `SignalGraph`.

## Проверки и отчёт

`groundstation_tests` проверяет модель и сигналы без GUI;
`groundstation_window_tests` проверяет реальные кнопки, общий таймер,
маршруты, графики, аварии и команды. CTest запускает окно через `offscreen`.
Для повторного получения скриншотов обязательных сценариев:

```sh
QT_QPA_PLATFORM=offscreen GROUNDSTATION_SCREENSHOTS="$PWD/report/screenshots" \
  ./build/groundstation_window_tests
```

Результаты, ограничения проверки звука/3D и скриншоты — в
[отчёте](report/REPORT.md).
